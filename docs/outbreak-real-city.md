# Outbreak real-city pipeline (experiment, P00–P01)

Status: **P01, geographic validation on real data.** P00 built the infrastructure on synthetic data. P01
runs it on about 1 km² of central Borås from a retained real-source snapshot and checks the result. Nothing
runs in Blender or Roblox Studio, and the Three.js game is unchanged. **The 1000 × 1000 m Borås dataset is
geographically validated, but it has not been proven suitable for Roblox rendering.** The first Roblox
proof of concept will use a representative subset of about 300 × 300 m from it (§12).

```
OSM ─▶ Wasteland preprocessing ─▶ city.json ─▶ pipeline/outbreak ─▶ OutbreakGeo.json ─▶ (later) Roblox chunk/building builder
       place · fetch_osm ·                     (adapter)                                 + OutbreakOverrides, GameplayLayer,
       fetch_terrain · prepare_city                                                        AssetManifest
```

```sh
.venv/bin/python pipeline/outbreak <slug>                                   # → cities/<slug>/outbreak/OutbreakGeo.json
.venv/bin/python pipeline/outbreak/snapshot.py verify pipeline/outbreak/snapshots/boras-p01
.venv/bin/python pipeline/outbreak/snapshot.py build pipeline/outbreak/snapshots/boras-p01 --out /tmp/OutbreakGeo.json
.venv/bin/python pipeline/outbreak/realcheck.py pipeline/outbreak/snapshots/boras-p01 --out /tmp/p01-report.json
.venv/bin/python -m unittest discover tests                                 # Wasteland + Outbreak P00 + P01 tests
```

## 1. Why the pipeline is cut after city.json

`prepare_city.py` makes every geographic decision in plain Python with Shapely, testable without
Blender: the local projection, clipping to the play area, building volumes from outlines and
`building:part`s, heights and storeys (tagged or guessed), disjoint ground classes (carriageway,
sidewalk, park …), the sea from coastlines, and terrain cleaned of buildings and trees. Everything
after it (`build_city.py` in Blender, `export_tiles.py`, `tiles.mjs`, `make_pack.py`) turns that into
Three.js render assets. Outbreak needs the decisions, not the assets.

The adapter reads city.json as it is, without changing it. city.json doesn't say which values were
mapped and which guessed, and it has already turned mapped materials and colours into Wasteland's
palette, so the adapter also reads `osm.json`: for provenance, for the mapped look, for road traversal tags
and for road node ids. Before converting, the adapter proves city.json is a clean build (§8), so the
Outbreak source is its own Wasteland city folder or a retained snapshot (§8), never a refined city (§9).

| city.json | OutbreakGeo |
|---|---|
| `buildings[].footprint`, `h`, `levels`, `kind`, `base`, `landmark` (+ osm.json tags) | `buildings`: geometry, heights, mapped facade/roof values, per-field provenance |
| `roads` (centrelines, widths) (+ osm.json tags and node ids) | `roads` (+ node ids, layer, traversal tags, chunk spans), `navigation.junctions`, `navigation.crossings` |
| `areas` (ground classes), `land` | `areas`: disjoint ground classes (water = play area − land) |
| `walls` (city walls) | `navigation.collision`, with the building footprints |
| `terrain` (height grid) | `terrain` (grid + vertical datum) |
| `style`, `colour`, `roof_style`, `roof_colour` (Wasteland's palette) | **dropped**: render choices; the art layer picks a look from the mapped values |
| `footprints` (Wasteland's 2D collision: no holes, game containers appended) | **not used**: collision comes from the buildings |
| `surfaces`, building `parts`, wall/water/outskirts meshes, `curbs`, `shore` | **dropped**: render triangle soup |
| `barriers` (containers), generated hedges/fences, scattered `trees`, `props`, `landmarks`, `places` | **dropped**: battle-game decoration and labels |

## 2. Blender is optional

Normal LOD B/C geometry will be built **Roblox-native** from reusable modular assets (facade, roof,
window and door kits in the AssetManifest), placed by a builder from OutbreakGeo's footprints,
heights and mapped materials. Blender is at most a special tool for a few unique LOD A assets (an
AssetManifest `special_mesh`, such as a cathedral). The adapter imports no `bpy`, reads no `.blend`,
needs no Blender run and uses none of Wasteland's render geometry.

## 3. Four documents, four jobs

| Document | Holds | Made by | Schema |
|---|---|---|---|
| **OutbreakGeo** | geographic truth: where things are and what they are, as mapped | generated by the adapter; never hand-edited | `outbreak_geo.v1` |
| **OutbreakOverrides** | geographic and art corrections: LOD class, storeys/height, building/facade/roof archetype, hide, replace | people; applied at build time (later) | `outbreak_overrides.v1` |
| **GameplayLayer** | Outbreak's changes: blocked roads, abandoned vehicles, barricades, zombie spawns, loot, safe/danger zones, interiors, routes | game design; schema only so far | `gameplay_layer.v1` |
| **AssetManifest** | reusable Roblox art: kits, modules, trim sheets, materials, special meshes, each with its licence | art; schema only so far | `asset_manifest.v1` |

The SourceManifest (`source_manifest.v1`) sits inside OutbreakGeo at `provenance.sources`; a retained
snapshot has its own `SNAPSHOT.json` (`real_snapshot.v1`). Schemas are standard JSON Schema in
`pipeline/outbreak/schemas/` (checked offline by `pipeline/outbreak/schema.py`), with examples in
`pipeline/outbreak/examples/`. What a schema can't say `adapter.check_geo` checks on the serialised
document from first principles, without rerunning the adapter: the declared frame (the WGS84 plane,
bounds a square centred on the place, the WGS84 box from the centre, the grid anchored at [0, 0], the
chunk count), ids, chunk references and the chunk index both ways, the owner rule, each span inside its
own chunk (half-open) and the spans covering the road inside the bounds segment by segment, polygon
validity, collision covering every ground-standing building, one position per OSM node id, junctions,
crossings and topology recomputed from the roads, and the terrain raster (n×n heights covering the
whole play area). The command line writes nothing that fails either. Corrections never go into
OutbreakGeo, and gameplay never goes into the overrides (the schema rejects it). Every correction
states its `basis` and a traceable `source`, and Street View isn't a basis.

## 4. Coordinates

- **Metres are canonical, and true.** OutbreakGeo uses city.json's local plane: origin at the place
  centre, x east, y north, z up. It must be the **WGS84 plane** (`place.json "projection": "wgs84"`,
  `common.Projection(lat0, lon0, 'wgs84')`): `x = (lon − lon0) · kx`, `y = (lat − lat0) · ky` with `kx`, `ky`
  the metres per degree from the WGS84 ellipsoid's prime-vertical and meridional radii at the centre
  (both written out in `metadata.coordinates.to_local`). Lengths are true to about 1.3e-4 within 500 m
  of the centre; a point's position is within about 7 cm of a geodesic (azimuthal-equidistant)
  reference anywhere in a 1 km square (measured in Borås: 0.071 m at most, §11).
- Wasteland's default plane (`'sphere'`: 111 320 m per degree, also east–west times cos lat0) is
  unchanged for the game, but its scale is off by up to about 0.7 % depending on latitude: −0.24 %
  east–west and −0.05 % north–south in Borås, 2.4 m over a kilometre. The adapter refuses a city built on
  it, and a terrain grid sampled on another plane than the city's (`terrain.json "projection"`).
- Rings: outer counter-clockwise, holes clockwise, no repeated closing point, always valid polygons
  (invalid input is refused, never repaired silently).
- Heights: `terrain.heights_m` (a grid that must cover the whole play area) are over the terrain datum
  (0 = the flat city's ground, 1.2 m above the main water; `vertical_datum` gives the way back to source
  heights). A building's `wall_height_m` and `min_height_m` are over its `base_m`. `wall_height_m` is
  the top of the walls (eaves), and a pitched roof rises above it.
- **Studs exist only at the Roblox edge**, through `pipeline/outbreak/units.py`:
  1 stud = 0.28 m, so **1 m = 1 / 0.28 ≈ 3.571428571 studs**. Axes: Roblox X = east, Y = up,
  Z = south (north is −Z), so `(x, y, z) m → (x, z, −y) / 0.28 studs`, the same handedness change as
  the Three.js game. No other code converts, and OutbreakGeo holds no stud values (tested).

## 5. Chunks

- A uniform **60 m** grid (≈ 214.3 studs) anchored at the place centre. Chunk `c{i}_{j}` is the
  half-open square `[60i, 60(i+1)) × [60j, 60(j+1))`, judged by those published borders themselves, so any
  chunk size works exactly (with 30.1 m, `floor(x / 30.1)` alone would be one off at x = −3 · 30.1). The
  play-area bounds are half-open too, and every chunk that overlaps them is listed: 36 for a 300 m
  square, 18 × 18 = 324 for 1000 m. A chunk's `bounds_m` is its part of the bounds, so edge chunks are
  narrower (20 m strips for 1000 m) and nothing is built outside the bounds.
- **Why 60 m (a candidate, not a tuned value):** it is Wasteland's own `cell`/streamed-tile size, so each
  building's owner chunk equals its city.json `cell`. A 300 m PoC gets 6 × 6 chunks. Several chunks fit
  inside Roblox's default streaming radius. Anchoring at the centre means growing the area never
  renumbers a chunk. P01 found no reason to change it (§11); measure in the PoC and change it with
  `--chunk-size`; nothing else depends on 60.
- **Crossing a border:**
  - *Buildings* are never split. `chunk` is the owner, where the building is placed once: the chunk
    holding its centroid, or the chunk it covers most if it doesn't reach that one. `chunks` lists every
    chunk it covers.
  - *Roads* keep their whole OSM centreline. `spans` cut the part inside the bounds by arc length
    (`s0_m … s1_m`, full precision) per chunk. Neighbouring spans share their end point exactly
    (`chunks.cut_line`). Every piece of positive length stays in the chunk it lies in, however short.
  - *Areas and collision outlines* list every chunk they cover with positive area. The builder cuts
    them per chunk with `chunks.clip_polygon(polygon, chunk.bounds_m)`.
  - A point on a border belongs to the higher chunk; an edge lying on a border touches only one chunk.
- **Ground classes are disjoint:** each piece of land has one class. prepare_city makes its layers
  disjoint and then simplifies each one on its own (0.8 m), so neighbouring layers can overlap a little
  in city.json; the adapter gives such ground to the layer prepare_city ranks higher and reports pieces
  under 0.01 m² it drops. Non-road classes are cut to the land; carriageway, pedestrian and path may lie
  over water, where they are bridge decks.
- `chunks[]` is the index a builder walks chunk by chunk: buildings owned there, and the roads, areas
  and collision outlines present. `check_geo` proves it matches the features both ways.
- **Deterministic:** features sorted by id, chunk lists sorted, canonical JSON (UTF-8, sorted keys,
  compact), warnings sorted and naming features by id. Identical input gives byte-identical output,
  whatever the order of features in city.json or osm.json (tested on synthetic and on real data).

## 6. Navigation

- `navigation.collision`: what blocks movement at ground level, each piece tied to its OSM outline
  (`osm`) and the building volumes inside it (`buildings`). Every mapped building outline standing on
  the ground blocks with its whole extent together with its volumes, **holes kept** (courtyards stay
  open) and **building passages and covered ways at ground level cut out**. What city.json leaves out
  still blocks (prepare_city drops an outline's leftover beside its `building:part`s when it is under
  20 %; reported). "Standing on the ground" is one rule for outlines and volumes: walls starting at most
  2.5 m up. Raised outlines and parts never block. City walls block too. `check_geo` proves every
  ground-standing building is covered by pieces that list it. These polygons are the source for cheap
  Roblox collision proxies.
- `roads[].drivable`: a highway class a car can physically drive on (pedestrian streets excluded).
  Legal rules are carried, not judged: `roads[].tags` holds `oneway`, `access`, `vehicle`,
  `motor_vehicle`, `bridge`, `tunnel`, `layer`, `covered`, `service`, `lanes`, `width` … verbatim (the
  highway and surface values are the road's `class` and `surface`), and `layer` parsed.
- **Road node identity.** Wasteland's download (`fetch_osm.py`) keeps every way's ordered OSM node ids
  beside its geometry (`nodes`, one per point, as Overpass gives them). city.json keeps each road's
  full OSM geometry rounded to centimetres, and the adapter attaches the ids to `roads[].nodes` only
  where the way in osm.json lines up with the centreline point for point (its geometry, projected and
  rounded as prepare_city does, is exactly the centreline). Otherwise `nodes` is null and a warning names
  the road, so an id can never land on the wrong vertex. `check_geo` refuses a node id at two positions.
- **Junctions** (`navigation.junctions`), where roads meet inside the bounds:
  - `basis: osm_node` — **verified**: an OSM node two or more roads share. That is topology: a bridge
    drawn over a street, or even through its node's position, has its own nodes and doesn't meet it.
  - `basis: shared_position` — **not verified**, the fallback where a road has no usable node ids:
    roads at one position on the same vertical level (below), at least one of them without an id
    there. Node null. Never upgraded to verified.
- **Crossings** (`navigation.crossings`): where two roads' centrelines meet in the plane inside the bounds
  without being joined there. Never a junction. `status: separated` when they lie on different vertical
  levels; `status: unresolved` when the source puts them on one level (or can't tell) yet they share no
  node (an unmapped junction, or roads that really pass each other); `differ` names the tags among
  layer, bridge, tunnel, covered and level whose values differ. The vertical level of a road: its `layer`
  when tagged, else 1 on a bridge, −1 in a tunnel (a `building_passage` runs at the ground), else 0, plus
  an indoor `level` other than 0. A covered way stays at its layer (a roof doesn't lift a street); an
  unreadable layer means "can't tell".
- `navigation.topology`: `osm_nodes` (every road has node ids), `mixed`, `positions` (none) or `none`.
  With `drivable`, the traversal tags, verified junctions and crossings, a road graph for the Runners'
  and vehicles' routes needs no geometry guessing.

## 7. LOD model

| LOD | What | Geometry |
|---|---|---|
| **A** | landmarks and gameplay buildings | optional unique meshes (maybe from Blender) and interiors |
| **B** | streets and facades near the player | modular reusable Roblox assets |
| **C** | background buildings | cheap geometry, heavy reuse |

Landmarks (Wasteland's rule: named churches, town halls, museums …) get `lod.class = "A"`
(`basis: "landmark"`) and everything else stays `null` (`unassigned`); OutbreakOverrides can set any
building's LOD by hand.

## 8. Provenance and reproducibility

- **city.json is verified, not trusted.** The adapter rebuilds city.json with `prepare_city` in a
  temporary folder from the folder's `place.json`, `osm.json` and `terrain.json` and the allowed build
  settings, with no refinements, and refuses the city unless the result equals the folder's city.json.
  prepare_city is deterministic (tested across hash seeds and processes); it can differ between machines
  with another GEOS, so rebuild city.json where you convert it.
- Every building and road field says where it came from: `osm` (the mapped value itself), `derived`
  (computed from OSM by a fixed rule), `default`, `inferred` (Wasteland's guess), `mixed`, `unknown`,
  `none`. The table is in `provenance.origins`, the origin of each ground class in
  `provenance.area_classes`.
- The **SourceManifest** pins every input by SHA-256 with the encoding it was read in, the code
  (SHA-256 of Wasteland's preprocessing and every adapter file and schema, line endings normalised;
  the git commit and a dirty flag; Python, Shapely, GEOS and NumPy versions), the OSM data time and
  download record, and the terrain source, tiles, projection and coverage.
- **When, and how current.** `fetch_osm.py` writes a `fetch` record into osm.json: this machine's clock
  when the download started and finished, and for every answer it was made of the source and how current
  that source says its data is (the OSM API's server time from its `Date` header, an Overpass mirror's
  `timestamp_osm_base`). `osm3s.timestamp_osm_base` is the oldest of those, so the data is at least that
  current; it is `null` (unknown) when a source states no time, never the download time instead. Each
  way keeps all its OSM node ids; a node missing from an answer leaves the geometry a point short, so the
  two lists no longer line up and the way is listed as incomplete (with any multipolygon still missing a
  member) instead of becoming an invisible shortcut. Overpass, which completes the multipolygons that reach
  outside the box, often answers 504; the completion is tried for up to three rounds of mirrors.
- **Retained snapshots** (`pipeline/outbreak/snapshot.py`, `SNAPSHOT.json` = `real_snapshot.v1`): live
  OpenStreetMap and terrain services are read **once**, by Wasteland's own `fetch_osm.py` and
  `fetch_terrain.py`, and their output is kept byte for byte: `place.json`, `osm.json.gz` and
  `terrain.json.gz` (gzip with mtime 0), each with the SHA-256 and size of the stored file and of its
  content, plus the download time, the download box, element counts, how many ways keep node ids, the
  terrain tiles, attribution, licence and coverage, and SHA-256 pins of the download code. `create` reads
  the repository's `.env` with Wasteland's own loader first (as `wasteland.py build` does), so Lantmäteriet
  credentials kept there are used, and refuses a download without a fetch record, with a way missing a
  node, with a multipolygon Overpass could not complete (the area would be missing) or with an OSM element
  whose source tags name Google or Street View. `fetch_terrain.py` counts fallback and no-data cells over the
  whole grid, the play area and the support (every cell prepare_city interpolates its terrain from: the play
  area, its 450 m terrain margin and one step), so a hole just outside the play area that still shapes
  heights inside it is visible. `verify` refuses
  a snapshot whose files don't match, whose metadata is malformed or disagrees with the files, which holds
  an unexpected file, or whose terrain has holes in the support (files from before the support was counted:
  anywhere in the grid) or the play area, or an unknown licence. `build` reads
  only the verified files: a fresh city folder, prepare_city, then the adapter with its clean-rebuild
  check and the contract. `snapshots/.gitattributes` keeps git from changing line endings, so a checkout
  on any platform verifies.
- **Encoding:** Wasteland on Windows writes JSON in the ANSI code page. The adapter reads UTF-8, else
  Windows-1252, the same under any locale or `PYTHONUTF8`, and records which; the clean rebuild and
  snapshot builds run prepare_city in Python's UTF-8 mode, so the bytes are the same under every locale.
- **One OSM identity, one content:** osm.json with two different entries for the same element is refused.

### Problems P01 found and fixed

- Wasteland's `/map` download dropped way node ids: kept now (`fetch_osm.py`), so topology is verified.
- Wasteland's plane is 0.24 % short east–west in Borås: the WGS84 plane, opt-in per place, required by OutbreakGeo.
- Overpass failures left multipolygons (the river) incomplete without stopping the fetch: snapshots refuse that.
- Wasteland's `/map` conversion hid a node missing from an answer by shortening the node list and the
  geometry together (an invisible shortcut); the full node list is kept now and the gap is reported.
- osm.json recorded no data time (Wasteland put the source name there); P01's first fix put this machine's
  download clock there. The download time and each source's own time are recorded apart now.
- `snapshot.py create` didn't read `.env`, so Lantmäteriet credentials kept there would have been missed.
- The completeness check counted features but not ground areas: a document without its parks, or without
  its sidewalks, or without a narrow path, passed. It checks every mapped area and the ground derived from
  the roads both ways now, piece by piece.
- fetch_terrain counted holes only inside the play area, though prepare_city interpolates heights at its
  edge from cells outside it: holes are counted over the whole support now.
- prepare_city's rounding to centimetres left 19 ground-class polygons invalid (rings pinched or crossing,
  a collapsed hole): such a polygon is now snap-rounded to the same grid, which keeps it valid (a polygon
  that rounds cleanly is written exactly as before), so the adapter stays strict.
- The adapter crashed on a building outline entirely outside the play area (in the download margin).
- fetch_terrain filled holes with the lowest height silently: it now records fallback and no-data cells.

### Known limitations

- Terrain is the 30 m Copernicus surface model, not Lantmäteriet's 1 m ground model (no credentials).
- Heights and storeys are mostly inferred (410 of 476); roof shapes too (435).
- Tunnels, rails, mapped hedges and fences, barrier nodes, trees and street furniture are not carried.
- Ground classes are Wasteland's simplified (0.8 m) unions without OSM ids; area ids are content hashes.
- An outline split round its `building:part`s leaves 0.2 m slits among the buildings (collision covers
  the whole outline).
- A build takes 1.5–4.5 minutes here, most of it Wasteland decoration; the OutbreakGeo hash includes the
  code pins and the generator commit and dirty flag, so it changes with the code (and when this is committed).
