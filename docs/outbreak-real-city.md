# Outbreak real-city pipeline (experiment, P00)

Status: **P00, infrastructure and feasibility only.** No real city is built, nothing runs in Blender
or Roblox Studio, and the Wasteland pipeline and game are unchanged. Everything new lives in
`pipeline/outbreak/`, `tests/test_outbreak.py`, `tests/outbreak_fixture.py` and this file.

```
OSM ─▶ Wasteland preprocessing ─▶ city.json ─▶ pipeline/outbreak ─▶ OutbreakGeo.json ─▶ (later) Roblox chunk/building builder
       place · fetch_osm ·                     (adapter)                                 + OutbreakOverrides, GameplayLayer,
       fetch_terrain · prepare_city                                                        AssetManifest
```

```sh
.venv/bin/python pipeline/outbreak <slug>               # → cities/<slug>/outbreak/OutbreakGeo.json
.venv/bin/python pipeline/outbreak <slug> --chunk-size 80 --out /tmp/geo.json
.venv/bin/python -m unittest discover tests             # Wasteland pipeline tests + Outbreak tests
```

## 1. Why the pipeline is cut after city.json

`prepare_city.py` makes every geographic decision in plain Python with Shapely, testable without
Blender: the local projection, clipping to the play area, building volumes from outlines and
`building:part`s, heights and storeys (tagged or guessed), disjoint ground classes (carriageway,
sidewalk, park …), the sea from coastlines, and terrain cleaned of buildings and trees. Everything
after it (`build_city.py` in Blender, `export_tiles.py`, `tiles.mjs`, `make_pack.py`) turns that into
Three.js render assets. Outbreak needs the decisions, not the assets.

The adapter reads city.json as it is, without changing it, and Wasteland keeps working exactly as
before. city.json doesn't say which values were mapped and which guessed, and it has already turned
mapped materials and colours into Wasteland's palette, so the adapter also reads `osm.json`: for
provenance, for the mapped look and for road traversal tags. Before converting, the adapter proves
city.json is a clean build (§7), so the Outbreak source is its own Wasteland city folder, made only
by `new` and `build --only fetch,terrain,prepare` and never refined (§8).

| city.json | OutbreakGeo |
|---|---|
| `buildings[].footprint`, `h`, `levels`, `kind`, `base`, `landmark` (+ osm.json tags) | `buildings`: geometry, heights, mapped facade/roof values, per-field provenance |
| `roads` (centrelines, widths) (+ osm.json tags) | `roads` (+ layer, traversal tags, chunk spans), `navigation.junctions` |
| `areas` (ground classes), `land` | `areas`: disjoint ground classes (water = play area − land) |
| `walls` (city walls) | `navigation.collision`, with the building footprints |
| `terrain` (height grid) | `terrain` (grid + vertical datum) |
| `style`, `colour`, `roof_style`, `roof_colour` (Wasteland's palette) | **dropped**: render choices; the art layer picks a look from the mapped values |
| `footprints` (Wasteland's 2D collision: no holes, game containers appended) | **not used**: collision comes from the buildings |
| `surfaces`, building `parts`, wall/water/outskirts meshes, `curbs`, `shore` | **dropped**: render triangle soup |
| `barriers` (containers), generated hedges/fences, scattered `trees`, `props`, `landmarks`, `places` | **dropped**: battle-game decoration and labels |

## 2. Blender is optional

Normal LOD B/C geometry will be built **Roblox-native** from reusable modular assets (facade, roof,
window and door kits in the AssetManifest), placed by a builder from OutbreakGeo's footprints,
heights and mapped materials. Blender is at most a special tool for a few unique LOD A assets (an
AssetManifest `special_mesh`, such as a cathedral). The adapter imports no `bpy`, reads no `.blend`,
needs no Blender run and uses none of Wasteland's render geometry.

## 3. Four documents, four jobs

| Document | Holds | Made by | Schema |
|---|---|---|---|
| **OutbreakGeo** | geographic truth: where things are and what they are, as mapped | generated by the adapter; never hand-edited | `outbreak_geo.v1` |
| **OutbreakOverrides** | geographic and art corrections: LOD class, storeys/height, building/facade/roof archetype, hide, replace | people; applied at build time (P01) | `outbreak_overrides.v1` |
| **GameplayLayer** | Outbreak's changes: blocked roads, abandoned vehicles, barricades, zombie spawns, loot, safe/danger zones, interiors, routes | game design; schema only in P00 | `gameplay_layer.v1` |
| **AssetManifest** | reusable Roblox art: kits, modules, trim sheets, materials, special meshes, each with its licence | art; schema only in P00 | `asset_manifest.v1` |

The SourceManifest (`source_manifest.v1`) sits inside OutbreakGeo at `provenance.sources`. Schemas are
standard JSON Schema in `pipeline/outbreak/schemas/` (checked offline by `pipeline/outbreak/schema.py`),
with examples in `pipeline/outbreak/examples/`. What a schema can't say `adapter.check_geo` checks on
the serialised document from first principles, without rerunning the adapter: the declared frame
(bounds a square centred on the place, the WGS84 box from the centre, the grid anchored at [0, 0],
the chunk count), ids, chunk references
and the chunk index both ways, the owner rule, each span inside its own chunk (half-open) and the spans
covering the road inside the bounds segment by segment, polygon validity, collision covering every
ground-standing building, junctions and topology from the roads' nodes, and the terrain raster (n×n heights
covering the whole play area). The
command line writes nothing that fails either. Corrections never go into OutbreakGeo, and gameplay
never goes into the overrides (the schema rejects it). Every correction states its `basis` and a
traceable `source` (reference, who, when; a licence for open data), and Street View isn't a basis.

## 4. Coordinates

- **Metres are canonical.** OutbreakGeo uses city.json's local plane unchanged: origin at the place
  centre, x east, y north, z up, equirectangular (`x = (lon − lon0) · 111320 · cos lat0`,
  `y = (lat − lat0) · 111320`; accurate to centimetres over a few km). Coordinates are copied, not
  recomputed.
- Rings: outer counter-clockwise, holes clockwise, no repeated closing point, always valid polygons
  (invalid input is refused, never repaired silently).
- Heights: `terrain.heights_m` (a grid that must cover the whole play area; the adapter refuses one that
  doesn't) are over the terrain datum (0 = the flat city's ground, 1.2 m above the
  main water; `vertical_datum` gives the way back to source heights). A building's `wall_height_m` and
  `min_height_m` are over its `base_m`. `wall_height_m` is the top of the walls (eaves), and a pitched
  roof rises above it.
- **Studs exist only at the Roblox edge**, through `pipeline/outbreak/units.py`:
  1 stud = 0.28 m, so **1 m = 1 / 0.28 ≈ 3.571428571 studs**. Axes: Roblox X = east, Y = up,
  Z = south (north is −Z), so `(x, y, z) m → (x, z, −y) / 0.28 studs`, the same handedness change as
  the Three.js game. No other code converts, and OutbreakGeo holds no stud values (a test checks this).
  The AssetManifest is Roblox-native, so its sizes are in studs and the field says so (`size_studs`).

## 5. Chunks

- A uniform **60 m** grid (≈ 214.3 studs) anchored at the place centre. Chunk `c{i}_{j}` is the
  half-open square `[60i, 60(i+1)) × [60j, 60(j+1))`, judged by those published borders themselves, so any
  chunk size works exactly (with 30.1 m, `floor(x / 30.1)` alone would be one off at x = −3 · 30.1). The
  play-area bounds are half-open too, and every
  chunk that overlaps them is listed: 36 for a 300 m square. A chunk's `bounds_m` is its part of the
  bounds, so edge chunks are narrower (30 m for a 300 m square) and nothing is built outside the bounds.
- **Why 60 m (a candidate, not a tuned value):** it is Wasteland's own `cell`/streamed-tile size, so
  each building's owner chunk equals its city.json `cell`. A 300 m PoC gets 6 × 6 chunks, neither one
  giant world model nor thousands of tiny ones. Several chunks fit inside Roblox's default streaming
  radius. Anchoring at the centre means growing the area never renumbers a chunk. Measure in the PoC
  and change it with `--chunk-size`; nothing else depends on 60.
- **Crossing a border:**
  - *Buildings* are never split. `chunk` is the owner, where the building is placed once: the chunk
    holding its centroid, or the chunk it covers most if it doesn't reach that one. `chunks` lists
    every chunk it covers. Every building has exactly one owner.
  - *Roads* keep their whole OSM centreline. `spans` cut the part inside the bounds by arc length
    (`s0_m … s1_m`, full precision, `s0_m < s1_m`) per chunk. Neighbouring spans share their end point
    exactly, so one piece per span leaves no gap (`chunks.cut_line`). Every piece of positive length
    stays in the chunk it lies in, however short (a line grazing a chunk corner by millimetres); only
    cuts that coincide numerically (a line through a grid corner) are merged.
  - *Areas and collision outlines* list every chunk they cover with positive area. The builder cuts
    them per chunk with `chunks.clip_polygon(polygon, chunk.bounds_m)`; the pieces add up to the whole
    and keep the contract's orientation (outer counter-clockwise, holes clockwise; tested).
  - A point on a border belongs to the higher chunk; an edge lying on a border touches only one chunk.
- **Ground classes are disjoint:** each piece of land has one class. prepare_city makes its layers
  disjoint and then simplifies each one on its own (0.8 m), so neighbouring layers can overlap a little
  in city.json; the adapter gives such ground to the layer prepare_city ranks higher (carriageway,
  sidewalk, pedestrian, path, parking, pitch, park, grass, cemetery, forest) and reports pieces under
  0.01 m² it drops. Non-road classes are cut to the land; carriageway, pedestrian and path may lie over
  water, where they are bridge decks. `check_geo` checks both.
- `chunks[]` is the index a builder walks chunk by chunk: buildings owned there, and the roads, areas
  and collision outlines present. `check_geo` proves it matches the features both ways.
- **Deterministic:** features sorted by id, chunk lists sorted, canonical JSON (UTF-8, sorted keys,
  compact). Identical input gives byte-identical output, whatever the order of features in city.json.
  One OSM element in several pieces gets `#1`, `#2` … by geometry, then content; exact duplicates
  collapse (with a warning); two entries with one id and one footprint but different values are refused.

## 6. Navigation

- `navigation.collision`: what blocks movement at ground level, each piece tied to its OSM outline
  (`osm`) and the building volumes inside it (`buildings`). Every mapped building outline standing on
  the ground (read from osm.json as prepare_city reads it) blocks with its whole extent together with
  its volumes, **holes kept** (courtyards stay open) and **building passages and covered ways cut
  out**. So what city.json leaves out still blocks: prepare_city drops an outline's leftover beside its
  `building:part`s when it is under 20 % of the outline, and the adapter reports the area it covers for
  it. A ground-standing volume no outline holds (a `building:part` mapped alone; every volume without
  osm.json) blocks on its own. "Standing on the ground" is one rule for outlines and volumes: walls
  starting at most 2.5 m up (`min_height`, else `building:min_level` storeys). Raised outlines and parts
  (overhangs, bridges between buildings) never block, and an overhang adds nothing to its outline's
  collision. A passage or covered way opens a building only at ground level (`layer` 0 and `level` 0,
  or untagged); a skyway on an upper floor leaves the house closed, and one whose layer or level can't
  be read is left closed and reported. City walls block too. Wasteland's `footprints` aren't used: they fill courtyards, miss parts without
  an outline and carry the battle game's edge containers. `check_geo` proves every ground-standing
  building is covered by pieces that list it. These polygons are the source for cheap Roblox collision
  proxies (one anchored part or union per piece, `CanCollide` on the proxy, not on the art).
- `roads[].drivable`: a highway class a car can physically drive on (pedestrian streets excluded).
  Legal rules are carried, not judged: `roads[].tags` holds `oneway`, `access`, `motor_vehicle`, `bridge`,
  `tunnel`, `layer` … verbatim, and `layer` parsed.
- `navigation.junctions`: where roads meet. Each road carries the OSM node id of every centreline
  vertex (`nodes`) when osm.json has them; a junction with `basis: osm_node` is a node two or more roads
  share, which is topology: a bridge drawn through a street's node position has its own nodes, so they
  cross without meeting. Where a road's node ids are unknown, roads at one position are listed as
  `basis: shared_position` (node null): possibly connected, not verified. `navigation.topology` says
  which holds for the whole place (`osm_nodes`, `mixed`, `positions`). With `drivable`, `layer` and
  node junctions, a road graph for the Runners' and vehicles' routes needs no geometry guessing.
- **Node ids need Overpass data.** Wasteland's primary download (the OSM API `/map`, `fetch_osm.py`)
  keeps only each way's geometry, so a city fetched that way has `topology: positions`. Keeping the
  node refs there is a small change to Wasteland's fetch step, left for the PoC phase (P00 doesn't
  change Wasteland's pipeline); until then, refetch the Outbreak source through Overpass or treat
  `shared_position` junctions as unverified.

## 7. LOD model

| LOD | What | Geometry |
|---|---|---|
| **A** | landmarks and gameplay buildings | optional unique meshes (maybe from Blender) and interiors |
| **B** | streets and facades near the player | modular reusable Roblox assets |
| **C** | background buildings | cheap geometry, heavy reuse |

In P00, landmarks (Wasteland's rule: named churches, town halls, museums …) get `lod.class = "A"`
(`basis: "landmark"`) and everything else stays `null` (`unassigned`). B or C depends on distance from
the routes players use, which the GameplayLayer will know, and OutbreakOverrides can set any building's
LOD by hand.

## 8. Provenance and reproducibility

- **city.json is verified, not trusted.** The adapter rebuilds city.json with `prepare_city` in a
  temporary folder from the folder's `place.json`, `osm.json` and `terrain.json` and the allowed build
  settings, with no refinements, and refuses the city unless the result equals the folder's city.json.
  A city.json built from other inputs, other code or with overrides (even ones removed afterwards) is
  caught. prepare_city is deterministic (tested across hash seeds); it can differ between machines with
  another GEOS, so rebuild city.json where you convert it. `policy.city_json` and
  `sources.inputs.city.clean_rebuild` say whether this check ran; only the library API (tests) skips it.
- Every building and road field says where it came from: `osm` (high confidence; the mapped value
  itself, not clamped or reduced), `derived` (computed from OSM by a fixed rule, such as a wall
  height from storeys or a tagged height minus the roof), `default`, `inferred` (Wasteland's guess,
  low: storeys, flat or pitched roof), `mixed`, `unknown` (no osm.json), `none` (OSM has no value). The
  table is in `provenance.origins`, and the origin of each ground class in `provenance.area_classes`
  (sidewalks are inferred; grass includes generated lawns). Facade and roof materials and colours are
  the OSM values verbatim, never Wasteland's palette.
- The **SourceManifest** pins every input by SHA-256 (place.json, city.json, osm.json, terrain.json,
  overrides.json if present, which then holds only build settings) with the encoding it was read in.
  It pins the code too: SHA-256 of Wasteland's preprocessing (`common.py`, `prepare_city.py`,
  `style.json`) and every adapter file and schema, line endings normalised, so a dirty checkout is still
  pinned; plus the git commit, a dirty flag and the Python, Shapely, GEOS and NumPy versions. It also
  records the terrain source and its tiles or STAC item ids, the place centre, bbox and size, and the
  Nominatim match. Downloading OSM again later gives different data, so archive `osm.json` and
  `terrain.json` with every build that matters.
- **Encoding:** Wasteland on Windows writes JSON in the ANSI code page. The adapter reads UTF-8, else
  Windows-1252, the same under any locale or `PYTHONUTF8`, and records which. The clean rebuild gets
  its inputs decoded by that rule and rewritten as ASCII JSON, and prepare_city runs in a child process
  in Python's UTF-8 mode, so it reads and writes alike under every locale and names outside cp1252 (Ł)
  work; the whole conversion gives the same bytes with `PYTHONUTF8` off and on (tested).
- **One OSM identity, one content:** osm.json with two different entries for the same element (tags,
  nodes or geometry) is refused instead of letting the input order pick one; identical repeats are one.
- **Determinism:** warnings name features by id, never by position in city.json, and are sorted, so the
  order of features in city.json or osm.json changes no byte of the output (tested on the whole
  document).
- Gaps, left for later because closing them means changing Wasteland's fetch step: `fetch_osm.py`
  keeps neither a download time nor per-element versions (its `timestamp_osm_base` holds the source
  name).

  to be clean. The adapter therefore **refuses any refined source folder**, and no option changes that:
  - `overrides.json` with anything but the build settings `defaults.terrain` (boolean) and
    `defaults.terrain_scale` (positive number): building, road or area entries, `defaults.max_levels`

  - `custom/*.py` or `refinements.md`, which show the folder has been refined.

  Behind that, the clean-rebuild check (§8) catches a city.json built with refinements that were
  removed afterwards. Corrections go into OutbreakOverrides, where every entry states an allowed
  `basis` and a traceable `source`, and Street View isn't a basis.

## 10. Gates for the later 300 × 300 m PoC

| Gate | Pass when |
|---|---|
| Road structure | streets connect as in OSM (junctions); widths, classes and layers match OutbreakGeo |
| Building placement | footprints at their OutbreakGeo positions; owner chunks as listed |
| Scale | 1 m = 1/0.28 studs throughout; a 3 m storey ≈ 10.7 studs |
| Driveable route | a vehicle can drive a planned route on drivable roads end to end |
| Collision | no driving or walking through buildings or city walls; courtyards and passages open; no invisible walls on streets |
| Runner navigation | Runners path along streets and open areas round the buildings |
| StreamingEnabled | the place runs with streaming on, chunk models streaming in and out |
| No streaming holes | no missing ground, roads or buildings at chunk borders while moving fast |
| FPS | measured on target devices along a representative route |
| Client memory | within a budget fixed before the PoC starts |
| Physical iPhone | tested on a real device, not only the emulator |
| ≥ 55 FPS representative run | sustained over the representative route on that iPhone |
| No Outbreak regression | Outbreak's existing modes, Runners, camera and movement unchanged |
| Reproducible build | same SourceManifest inputs and code → byte-identical OutbreakGeo → same place |

## Not in P00

No real city, no network calls in tests, no Blender, no `.blend`/GLB/FBX, no Roblox place, models or
assets, no change to `game/` or the Three.js runtime, no port of `tiles.mjs`, no change to the Outbreak
repository (Runners, camera, movement), no interiors or final art, no tuning for city sizes P00 doesn't
need. OutbreakOverrides is defined but not applied yet.

Known limits of the input: city.json's ground classes are simplified (0.8 m) unions without names or
OSM ids (area ids are content hashes, stable only for identical input), and pieces under 25 m² are
dropped by Wasteland. Wasteland leaves out tunnels (other than building passages), so roads under
ground are missing. An outline split round its `building:part`s leaves 0.2 m slits between the parts
and the remainder among the buildings (collision covers the whole outline, so they don't open). Roof rise, raised water levels (they are in
the terrain grid), trees, street furniture and rails aren't carried over yet. On Windows, the existing
selftest needs `PYTHONUTF8=1` (it fails in `make_pack.py` otherwise, unrelated to this experiment).
